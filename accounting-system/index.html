MOC — 회계 시스템 구조

2026-06-07 하루에 수집한 금융/회계 시스템 엔지니어링 컬렉션. 복식부기 기초 → 설계 원칙 → 빅테크 실전 사례 → 아키텍처 조감도 → ERP 구현 순.

종합 리서치

  • 빅테크 서브레저·회계 시스템 아키텍처 리서치 — 아래 자료들을 관통하는 자체 리서치 정리 (Sub-ledger/GL 2계층 공통 구조 → 데이터 수신·모델링 심화). 요약본이 필요하면 여기부터.

추천 읽기 순서

1단계 — 기초

  1. Accounting For Software Engineers (2017)
    엔지니어를 위한 복식부기 기초. 차변/대변, 분개, 원장을 SQL 멘탈모델로. "회계 개념은 발명하지 마라, 523년 됐다."
  2. Engineering Principles for Building Financial Systems
    금융 시스템 설계 원칙 — 정확성·신뢰성을 위한 베스트 프랙티스.

2단계 — 조감도

  1. What does a "finance system architecture" in a bank actually look like?
    은행 금융 아키텍처 레이어 맵: 원천 시스템 → 보조원장 → GL → 대사·통제 → 데이터 보정 → 보고. 댓글 하이라이트 필독 ("수작업 조정을 죽여라").

3단계 — 빅테크 실전 사례

  1. Tracking the money — Scaling financial reporting at Airbnb
    재무 리포팅 파이프라인 스케일링, 보조원장 = 단일 진실 공급원.
  2. Uber’s Finance Computation Platform
    연 400억 분개를 GAAP 준수·멱등·재현 가능하게 처리하는 플랫폼.
  3. Part I: Scaling Robinhood Clearing Accounting
    증권 청산 회계 — Kafka+Postgres 동기 트랜잭션 → 비동기 파이프라인 전환, 처리량 10배. 체결/원장/잔액의 원자성 요구 분해가 핵심. (Part II 예고: 스토리지 수평 확장)
  4. Ledger: Stripe’s system for tracking and validating money movement (2024)
    돈 이동 추적·검증 — 불변(immutable) 원장 + 데이터 품질 메트릭(적시성·완전성).

4단계 — ERP 구현 (Oracle)

  1. Accounting Event Flow — From Subledger to General Ledger in Oracle Fusion
    Oracle Fusion의 보조원장→GL 이벤트 흐름: Unaccounted → Accounted → Transferred → Posted.
  2. Oracle Accounting Hub
    Oracle Accounting Hub 제품 관점 — 이기종 시스템 회계 데이터 통합, 전사 계정 코드집.

관통하는 주제

  • 보조원장(subledger)이 진짜 일꾼 — 운영 데이터→회계 분개 변환은 전부 여기서. GL은 통합·보고용.
  • 원자성 분해가 스케일링의 열쇠 — "전부 한 트랜잭션"을 최종 일관성(eventually consistent)으로 풀어내는 것 (Robinhood·Uber).
  • 데이터 통제·보정 레이어가 가장 과소투자됨 — 보고 도구가 아니라 상류(upstream) 자동 통제가 품질을 결정 (Marot 댓글).
  • 불변 원장 + 감사 추적 — 숫자를 원천까지 추적 못 하면 아키텍처가 깨진 것 (Stripe·Vamshi).
