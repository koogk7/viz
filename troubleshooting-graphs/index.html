시계열에서 스택까지

2026-11 · 예시 데이터로 그린 그림

무엇을 알고 싶은가? 네 가지 질문

언제 나빠졌나

시계열 · RED/USE 라인 차트

얼마나 나쁜가

분포 · 히스토그램·퍼센타일·히트맵

어느 요청·단계인가

트레이스 · 워터폴·서비스 맵

어느 코드인가

스택 · 플레임 그래프·오프 CPU

도구 예: Grafana · Jaeger · Pyroscope · perf

어떤 순서로 그림을 꺼내는가?

도구 예: Grafana → Tempo/Jaeger → Pyroscope · async-profiler

사용자는 지금 괜찮은가? (RED)

  • 축시간 × Rate·Errors·P99
  • 읽기배포선과 겹치면 그것부터
  • 순간알림이 울린 직후 첫 그림
  • 함정평균 Duration은 평평할 수 있다

도구 예: Grafana · Prometheus · Datadog

이 자원은 한계에 가까운가? (USE)

  • 축시간 × 사용률·포화·에러
  • 읽기RED와 같은 시간축에 놓기
  • 순간자원(CPU·디스크)이 의심될 때
  • 함정포화는 사용률 90% 넘어서 폭발

도구 예: node_exporter · vmstat · Grafana

평균 뒤에 숨은 꼬리는 얼마나 긴가?

  • 축지연 구간 × 건수
  • 읽기봉우리 2개 = 요청 두 종류
  • 순간평균과 체감이 다를 때
  • 함정서버별 P99를 평균내지 말 것

도구 예: Prometheus histogram · HdrHistogram

꼬리만 자라고 있지 않은가?

  • 축시간 × P50·P95·P99
  • 읽기P50 평평, P99만 상승 = 꼬리 장애
  • 순간알림 기준은 P99에, 배포 전후 비교
  • 함정퍼센타일 창 크기를 명시할 것

도구 예: histogram_quantile · Grafana · Datadog

지연의 모양이 언제 바뀌었는가?

  • 축시간 × 지연 구간, 색=건수
  • 읽기띠가 몇 겹인지, 언제 생겼는지
  • 순간히스토그램을 시간순으로 보고 싶을 때
  • 함정색 농도는 선형이 아닐 수 있다

도구 예: Grafana Heatmap · Datadog Distribution

한 요청의 시간은 어디서 쓰였는가?

  • 축요청 1건 안의 스팬 × 시간
  • 읽기길이보다 직렬 개수
  • 순간느린 트레이스 1건을 잡았을 때
  • 함정정상 트레이스와 나란히 볼 것

도구 예: Jaeger · Tempo · Zipkin · OpenTelemetry

CPU 시간은 어느 코드가 먹는가?

  • 축가로=비중, 세로=호출 깊이
  • 읽기넓고 평평한 꼭대기를 찾는다
  • 순간CPU가 어디로 가는지 모를 때
  • 함정색·좌우 순서는 의미 없음

도구 예: perf · async-profiler · py-spy · Pyroscope

같은 스택을 뒤집거나 시간순으로 펼치면?

  • 축아이시클=뒤집기, 차트=실제 시간
  • 읽기아이시클은 같은 정보를 위에서 아래로
  • 순간DevTools Performance가 이 모양
  • 함정플레임 차트는 합산되지 않는다

도구 예: Chrome DevTools Performance · speedscope

숫자로 비교하려면 어떤 모양인가?

  • 축함수별 self%·total%
  • 읽기정확한 비교는 트리, 역추적은 bottom-up
  • 순간비중을 숫자로 못 박을 때
  • 함정선버스트는 보기 좋지만 비교 어렵다

도구 예: pprof · Chrome DevTools Bottom-Up · Pyroscope

수정은 정말 효과가 있었는가?

  • 축전후 비중 차이 (파랑↓ 빨강↑)
  • 읽기빨강은 회귀 후보
  • 순간수정 검증의 마지막 그림
  • 함정전후 부하·조건이 같아야 한다

도구 예: difffolded.pl · Pyroscope diff · pprof -diff_base

CPU는 한가한데 왜 느린가?

  • 축가로=대기 시간 (오프 CPU)
  • 읽기꼭대기가 lock·socket·futex
  • 순간CPU는 낮은데 지연은 클 때
  • 함정온 CPU와 합쳐야 요청 지연 전체

도구 예: bcc offcputime · perf sched · async-profiler wall

장애는 어느 서비스로 번지는가?

  • 축서비스 × 호출 관계
  • 읽기굵기=호출량, 빨강=에러율
  • 순간장애 전파 경로를 따라갈 때
  • 함정간선 지연·순환 호출도 확인

도구 예: Kiali · Jaeger DAG · Datadog Service Map

그림을 읽다 자주 틀리는 곳은?

  • 색은 무의미난색은 구분용일 뿐, 뜨거움이 아니다
  • 좌우 ≠ 시간플레임 그래프는 알파벳 순 합산
  • 좁고 높은 탑 ≠ 병목깊어도 폭이 좁으면 비중은 작다
  • 샘플이 적으면 폭을 불신수백 샘플 미만이면 흔들린다
  • 짧은 스팬 직렬 수십 개하나는 짧아도 합이 길다
  • 평균이 평평해도 꼬리는 자란다P99·히스토그램으로 확인

꺼내기 전 점검표와 출처

  • 배포 시각과 겹치는지 본다
  • 평균 말고 P99·히스토그램
  • 느린·정상 트레이스를 나란히
  • 가장 긴 스팬: 외부 vs 자기 코드
  • 플레임 또는 오프 CPU로 코드까지
  • 수정 후 같은 그림으로 재확인
