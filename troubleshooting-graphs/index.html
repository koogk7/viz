트러블슈팅 그래프 입문: 언제 어떤 그림을 꺼내는가

Long image

A

Answer

장애·성능 문제를 쫓을 때 쓰는 그래프는 네 가지 질문 중 하나에 답한다. 언제 나빠졌나(시계열), 얼마나 나쁜가(분포), 어느 요청·단계인가(트레이스), 어느 코드인가(스택). 플레임 그래프는 마지막 질문, 즉 "CPU 시간을 어느 함수가 먹는가"에 답하는 그림이다. 순서는 보통 시계열에서 시작해 스택으로 내려간다.

  1. 시계열은 증상의 시각과 범위를 주지만 원인은 주지 않는다.1
  2. 분포 그림은 평균이 숨기는 꼬리(P99)를 드러낸다.2
  3. 트레이스는 한 요청이 어느 서비스·단계에서 시간을 썼는지 보여 준다.3
  4. 스택 그림은 그 단계 안에서 어느 함수가 범인인지 좁힌다.4

네 질문과 그래프의 대응

질문그래프가로축 · 세로축꺼내는 순간
언제 나빠졌나시계열(RED·USE·골든 시그널)시간 · 비율·건수알림이 울렸을 때, 배포 전후 비교
얼마나 나쁜가히스토그램 · 퍼센타일 · 지연 히트맵지연값 · 건수(또는 시간)꼬리 확인평균은 정상인데 불만이 올 때
어느 요청·단계인가트레이스 워터폴(간트) · 타임라인시간 · 스팬(호출 단계)느린 요청 하나를 잡았을 때
어느 코드인가플레임 그래프 · 아이시클 · 콜 트리 · 선버스트시간 비중 · 스택 깊이원인 확정한 프로세스가 CPU를 먹을 때
왜 기다리나오프 CPU 플레임 그래프 · 락 프로파일대기 시간 비중 · 스택 깊이CPU는 놀고 지연만 긴 경우
누가 누구를 부르나서비스 의존 그래프(서비스 맵)노드 · 호출 간선장애 전파 경로를 찾을 때
2

진단은 어떤 순서로 내려가나

Diagram structure
  • 시계열 알림 alert
  • 분포로 꼬리 확인 tail
  • 느린 트레이스 선택 trace
  • 긴 스팬 찾기 span
  • 플레임 그래프 flame
  • 수정 후 재측정 fix
  • alert → tail · 언제
  • flame → fix · 함수 확정
  • span → flame · CPU 소모
  • tail → trace · 꼬리만 나쁨
  • trace → span · 요청 하나
  1. 시계열 알림 ↗

    에러율·지연·트래픽·포화도 중 무엇이 먼저 움직였는지 시각을 맞춘다. 배포·설정 변경 시각과 겹치면 그것부터 의심한다.

  2. 분포로 꼬리 확인 ↗

    같은 구간의 히스토그램이나 P50·P99를 본다. P99만 올랐으면 일부 요청의 문제, 전체가 올랐으면 자원 포화를 본다.

  3. 느린 트레이스 선택 ↗

    꼬리에 속한 요청 몇 개를 트레이스 ID로 집어낸다. 정상 요청 하나도 함께 열어 비교한다.

  4. 긴 스팬 찾기 ↗

    워터폴에서 가장 긴 막대와 직렬로 늘어선 막대를 찾는다. 외부 호출이면 그 서비스로, 자기 코드면 다음 단계로 간다.

  5. 플레임 그래프 ↗

    그 프로세스를 프로파일링해 넓고 평평한 꼭대기를 찾는다. CPU가 놀고 있으면 오프 CPU 그래프로 바꾼다.

  6. 수정 후 재측정 ↗

    고친 뒤 같은 그래프를 다시 그려 막대가 줄었는지 본다. 전후 차이는 차등 플레임 그래프로 확인한다.

3

스택을 보는 그림은 서로 무엇이 다른가

모두 호출 스택 샘플을 그린다. 다른 점은 시간을 합치는지, 어느 방향으로 쌓는지, 정렬 기준이 무엇인지다.4

그림가로축세로 방향강점한계
플레임 그래프샘플 비중(시간 순서 아님, 알파벳 정렬)아래가 진입점, 위로 호출한눈에넓은 꼭대기가 곧 병목호출 순서와 시점을 잃는다
아이시클 그래프샘플 비중위가 진입점, 아래로 호출깊은 스택을 스크롤 없이 봄플레임과 뒤집힌 것뿐, 같은 정보
플레임 차트실제 시간축아래가 진입점순서 보존어느 시점에 무엇이 돌았는지 보임같은 함수가 흩어져 합산이 안 됨5
콜 트리(top-down · bottom-up)표(비중 열)접고 펴는 트리숫자로 정확히 비교, bottom-up은 호출자 역추적전체 모양을 한눈에 못 봄
선버스트각도 비중안쪽이 진입점, 바깥으로 호출보기 좋고 집약적바깥 고리 글자가 작아 비교가 어려움
차등 플레임 그래프샘플 비중아래가 진입점수정 전후 늘고 줄어든 함수를 색으로 표시두 프로파일 조건이 같아야 뜻이 있다
4

시간 축을 보는 그림은 무엇을 나누나

그림한 화면에 담는 것단위묻는 것
시계열 · RED서비스 하나의 요청률(Rate)·에러(Errors)·지연(Duration)분·시간사용자 체감이 언제 변했나6
시계열 · USE자원 하나의 사용률(Utilization)·포화(Saturation)·에러(Errors)분·시간CPU·디스크·네트워크 중 어느 자원이 찼나7
트레이스 워터폴요청 하나의 스팬들밀리초어느 서비스·쿼리가 늘어졌나, 직렬인가 병렬인가3
타임라인배포·알림·조치 같은 사건분사건 순서와 간격, 회고용

RED는 "서비스가 사용자에게 어떤가", USE는 "자원이 어떤가"를 묻는다. 둘을 같은 시간축에 놓으면 증상과 자원이 이어진다.

5

분포를 보는 그림은 왜 따로 있나

평균과 P50은 전체 요청의 1퍼센트가 10배 느려져도 거의 움직이지 않는다. 그래서 꼬리를 보는 그림이 따로 있다.2

그림보여 주는 것꺼내는 순간
히스토그램한 구간의 지연값 분포. 봉우리가 두 개면 두 종류의 요청이 섞인 것느린 요청이 한 종류인지 확인할 때
퍼센타일 시계열(P50·P95·P99)시간에 따른 꼬리 변화알림 기준을 정할 때, 배포 전후 비교
지연 히트맵가로 시간, 세로 지연값, 색이 건수. 히스토그램을 시간축으로 늘어놓은 것꼬리가 언제 생겼고 몇 겹인지 볼 때8

퍼센타일을 합칠 때

서버별 P99를 평균 내면 P99가 아니다. 합치려면 원본 히스토그램을 합친 뒤 다시 계산한다. 1분 창의 P99와 1시간 창의 P99는 다른 값이다. 창 크기를 적어 두고 비교한다.

6

CPU가 놀고 있는데 느리면 무엇을 보나

플레임 그래프는 CPU에서 실행 중인 스택만 샘플한다. 락 대기, 디스크·네트워크 I/O, 스레드 풀 대기는 보이지 않는다. 이때는 스레드가 CPU를 떠나 있던 시간을 스택별로 합친 오프 CPU 플레임 그래프를 그린다.9

읽는 법은 같다. 넓은 막대가 가장 오래 기다린 지점이다.

읽을 때 자주 틀리는 것

  • 플레임 그래프의 색은 대개 의미가 없다. 난색 계열을 무작위로 칠한다. 차등 그래프만 색이 뜻을 가진다.
  • 플레임 그래프의 가로 순서는 시간 순서가 아니다. 왼쪽 막대가 먼저 실행된 것이 아니다.
  • 좁고 높은 탑은 깊은 호출일 뿐 병목이 아니다. 넓고 평평한 꼭대기를 찾는다.
  • 샘플링 프로파일러는 짧은 함수를 놓칠 수 있다. 샘플 수가 적으면 폭을 믿지 않는다.
  • 트레이스 워터폴에서 긴 막대 하나보다 짧은 막대가 직렬로 수십 개 늘어선 쪽이 더 큰 원인일 수 있다.
  • 시계열이 평평해도 히스토그램은 변할 수 있다. 평균이 그대로인 채 꼬리만 자라는 경우다.
